statement_cache_size: 0 -> Setting it to 0 tells asyncpg to never name or store prepared statements in its internal LRU cache. Every query is executed as an unnamed, one-off statement that is discarded immediately after execution.
prepared_statement_cache_size: 0 -> Setting this to 0 prevents SQLAlchemy from attempting to manage or track prepared statements on the connection adapter.

            async def create_pregnancy(data: PregnancySchema, user_id: uuid.UUID, db: AsyncSession):
                try:
                    # 1. Prepare payload outside of the DB transaction
                    payload = data.model_dump(exclude_unset=True)
                    payload["user_id"] = user_id

                    # 2. Extract fields to update if row already exists
                    update_values = {
                        k: v for k, v in payload.items() 
                        if k != "user_id" and v is not None
                    }

                    # 3. Construct single atomic PostgreSQL Upsert
                    stmt = (
                        insert(PregnancyModel)
                        .values(**payload)
                        .on_conflict_do_update(
                            index_elements=[PregnancyModel.user_id],  # Requires UNIQUE constraint or PK on user_id
                            set_=update_values
                        )
                        .returning(PregnancyModel)
                    )

                    # 4. Single DB round-trip: executes write and returns updated model
                    result = await db.execute(stmt)
                    await db.commit()
                    
                    return result.scalars().one()

                except Exception as e:
                    await db.rollback()
                    raise HTTPException(status_code=400, detail=f"Error creating pregnancy: {str(e)}")
    
The Bottle neck Right now:
    1. In src/utils/db.py, poolclass=NullPool forces asyncpg to establish a brand-new TCP socket and TLS/SSL handshake to Supabase (aws-1-ap-northeast-2.pooler.supabase.com) on every single incoming HTTP request.
        Network handshake to remote cloud databases adds 150ms–250ms of idle waiting before queries even start. Under concurrent Locust load, this single factor restricts throughput to ~10–15 RPS.
    2. In write endpoints (update_daily_log, create_pregnancy, update_user, delete_periods), the code first fires a SELECT query across the internet just to check if a row exists, then fires the INSERT/UPDATE/DELETE.
    3. After await db.commit(), each controller executes await db.refresh(model). This triggers another full round-trip SELECT. Since expire_on_commit=False is already configured on the session, SQLAlchemy preserves model attributes, making extra refresh calls unnecessary when combined with PostgreSQL RETURNING.

Solution-1:
    Configure pool parameters for production high-concurrency:
    pool_size=20: Keeps 20 warm database connections ready in memory.
    max_overflow=10: Allows bursting up to 30 concurrent connections under load spikes.
    pool_recycle=300: Refreshes connections every 5 minutes to prevent stale disconnections from Supabase.
    pool_pre_ping=True: Verifies connection health before use, preventing broken pipe exceptions.
    Maintain "statement_cache_size": 0 in connect_args for full Supabase PgBouncer compatibility.

Solution-2 (Atomic Upsert)(Example below, replaced all the write functions like this):
    Current: SELECT -> check exists -> INSERT or UPDATE -> COMMIT -> REFRESH (4 round trips).
    Optimization: Use PostgreSQL native atomic UPSERT with RETURNING:
        from sqlalchemy.dialects.postgresql import insert as pg_insert
        stmt = (
            pg_insert(DailyLogModel)
            .values(user_id=user_id, **data.model_dump(exclude_unset=True))
            .on_conflict_do_update(
                constraint="unique_daily_log_per_user",
                set_=data.model_dump(exclude_unset=True)
            )
            .returning(DailyLogModel)
        )
        result = await db.execute(stmt)
        log = result.scalars().one()
        await db.commit()
        return log

    Round trips reduced from 4 to 1 query + commit.
